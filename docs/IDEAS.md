## 2. Сделано

### Проверка сайтов
- ✅ Сканирование настоящим браузером: трекеры и cookies **до** согласия, формы, ссылки, документы
- ✅ 30+ правил: 152-ФЗ (политика, согласие, отдельный документ согласия, cookies, иностранные сервисы, локализация, спецкатегории), 149-ФЗ, 38-ФЗ (маркировка, рассылки), ЗоЗПП, 436-ФЗ, 53-ФЗ, HTTPS
- ✅ Профиль сайта: тип бизнеса, платформа (Wix/Shopify/… = данные за рубежом), назначение каждой формы, реквизиты владельца, сервисы
- ✅ Отраслевые проверки: медицина, обучение, финансы, БАД, алкоголь/табак — только для основного профиля сайта
- ✅ Распознавание защиты от ботов (повтор, диагностика, скриншот) вместо ложного отчёта
- ✅ Аудит правил на 1c-bitrix.ru и tilda.ru: исправлено 9 ложных срабатываний (служебные формы, всплывающее согласие Битрикса, GTM, «18+» в тексте, «отел» в «хотели» и др.)

### Скорость и нагрузка
- ✅ Гибридная загрузка: внутренние страницы без JavaScript — HTTP-запросом (в 3,4 раза быстрее при тех же результатах)
- ✅ Первые результаты через 10–20 с (только найденные проблемы, без балла), затем полный отчёт
- ✅ «Осталось примерно N мин» для посетителя
- ✅ Глубина проверки (5–500 страниц) и число одновременных проверок — в админке, без перезапуска
- ✅ График нагрузки на дашборде: одновременные проверки, ожидание посетителей, пики
- ✅ Метки `utm`/`gclid`/… отрезаются, дубли страниц не съедают лимит

### Реестр РКН
- ✅ Проверка ИНН в реестре операторов ПДн через портал pd.rkn.gov.ru (без капчи, кеш 30 дней, ссылка на карточку)
- ✅ Выяснено: открытых данных реестра РКН больше не публикует; у DaData такого признака нет
- 🟡 Сверка карточки оператора с сайтом — см. раздел 3
- ✅ Регистрационный номер из реестра подставляется в политику

### Документы и решения
- ✅ Документы под сайт по фактам проверки: политика, согласие, тексты чекбоксов, согласие на рассылку, cookie-баннер с блокировкой метрик, правила рекомендательных технологий; просмотр, копирование, .docx
- ✅ «Как исправить на 1С-Битрикс / Tilda / WordPress» в карточках нарушений
- ✅ Кнопка «Это ошибка?» и «У нас есть уведомление в РКН» в отчёте

### Админка
- ✅ Дашборд, проверки (со скриншотами, диагностикой, временем по этапам), сайты, обратная связь
- ✅ Реестр нарушений с редактированием штрафов (сразу применяется ко всем отчётам), выгрузка CSV
- ✅ Пакетная проверка до 500 сайтов: пауза, продолжить, начать заново, повторить неудачные, список сайтов для копирования, документы всех сайтов (ZIP)
- ✅ Выгрузка истории для аудита: отчёты, скриншоты, снимки данных; скрипт повторного прогона правил на истории

### Инфраструктура
- ✅ VPS, Docker, nginx, HTTPS, деплой из GitHub (`deploy.sh`), smoke-тест
- ✅ Политика и согласие самого сервиса (страницы есть; реквизиты — см. раздел 1)

## 5. Идеи: польза, которой нет у ИИ

Принцип: ИИ **рассуждает** о сайте, сервис **наблюдает и доказывает** — реальные запросы браузера, реестры, доказательства, наблюдение во времени.

| | Идея | Ценность |
|---|---|---|
| 💡 | **PDF-протокол проверки** с датой, скриншотами, журналом запросов к трекерам и контрольной суммой | Доказательство для юриста, руководителя, подрядчика, спора |
| 💡 | **Цитата-обоснование** у каждого вывода + ссылка на норму | Доверие к отчёту, меньше споров «это ошибка» |
| 💡 | **Сверка с ЕГРЮЛ** через DaData (10 000 бесплатных запросов в день) | Реквизиты на сайте = ЕГРЮЛ? Компания действует? Адрес совпадает? Заодно — точные реквизиты в документах |
| 💡 | **Реестры лицензий** (Рособрнадзор, Росздравнадзор) | Проверка действующей лицензии клиники/школы по ИНН вместо поиска слова «лицензия» |
| 💡 | **Адресные новости законодательства** | «С 1 марта на вашем сайте нужно изменить вот это» — по профилю сайта |
| 💡 | **Маркировка рекламы**: проверка токенов erid | Сейчас проверяется только наличие erid/пометки |
| 💡 | **Мобильная версия сайта** | Cookie-баннер и формы на телефоне часто другие |
| 💡 | **Политика в PDF** | Разбор содержания политики, опубликованной файлом |
| 💡 | **ИИ точечно** (GigaChat / YandexGPT) | Только для анализа текста политики и типа бизнеса, с цитатой, которую проверяет код; только после эталонной выборки |

## 7. Техника и надёжность

| | Задача | Почему важно |
|---|---|---|
| 📋 | **Резервные копии базы данных** (ежедневно, вне сервера) | Сейчас при поломке диска пропадут вся история, реестр нарушений с правками юриста и обратная связь |
| 📋 | **Отдельный пользователь для деплоя, вход по ключу** | Сейчас вход root по паролю; после настройки ключа — запретить вход по паролю |
| 💡 | **Доступ к админке только с ваших IP** (ограничение в nginx) или второй фактор при входе | Сейчас админка защищена одним паролем (с ограничением 10 попыток за 15 минут) |
| ✅ | Права `.env` — только владелец; пароль в smoke-тесте не виден в списке процессов | Сделано в deploy.sh / smoke.sh |
| 📋 | **Мониторинг сервера и оповещения** | Узнать, что воркер упал или кончается диск, раньше пользователей |
| 📋 | **Ротация логов Docker** | Чтобы логи не заняли диск |
| 💡 | **Миграции базы через Alembic** | Сейчас простые миграции при старте API; при усложнении схемы понадобятся полноценные |
| 💡 | **Сервер 4 ядра / 8 ГБ** | См. раздел 1 |
